# RN-06: Reglas de Presentación de Proyectos

## Definición

Los proyectos son el contenido más valioso del portafolio. Cada proyecto debe presentarse como un caso de estudio que demuestre criterio técnico, no solo habilidad de código.

---

## Criterios de Validación

### Cantidad y Selección
1. [ ] Se muestran entre 3 y 5 proyectos destacados
2. [ ] El proyecto más impactante aparece primero
3. [ ] Los proyectos demuestran diversidad tecnológica
4. [ ] No hay proyectos basados en tutoriales genéricos

### Estructura del Caso de Estudio
5. [ ] Cada proyecto tiene un resumen ejecutivo claro
6. [ ] Se describe el problema que resolvía
7. [ ] Se documentan las decisiones técnicas y trade-offs
8. [ ] Se incluyen métricas de impacto (si están disponibles)
9. [ ] Hay enlaces a repositorio y demo

### Contenido Técnico
10. [ ] Los fragmentos de código son relevantes y están comentados
11. [ ] Los diagramas de arquitectura son claros
12. [ ] Se justifica la selección de tecnologías
13. [ ] Se mencionan las alternativas evaluadas

### Enlaces
14. [ ] El repositorio de GitHub es público y funciona
15. [ ] La demo en vivo está desplegada y funcional
16. [ ] Los enlaces abren en nueva ventana
17. [ ] Los enlaces tienen `rel="noopener noreferrer"`

### Diseño
18. [ ] Cada proyecto tiene thumbnail representativo
19. [ ] Las imágenes están optimizadas (WebP/AVIF)
20. [ ] El layout del caso de estudio es legible
21. [ ] Los fragmentos de código tienen syntax highlighting

## Plantilla de Caso de Estudio

```markdown
# [Nombre del Proyecto]

## Resumen
[1-2 párrafos: qué hace, para quién, resultado]

## Problema
[Qué necesidad o desafío motivó el desarrollo]

## Solución
[Qué se construyó y por qué]

## Arquitectura
[Diagrama y justificación de decisiones]

## Tecnologías
[Stack usado y por qué sobre alternativas]

## Resultados
[Métricas: latencia, usuarios, errores, etc.]

## Lecciones
[Qué se aprendió y qué se haría diferente]

## Enlaces
- [GitHub](URL)
- [Demo](URL)
```

---

## Excepciones

- Los proyectos en desarrollo pueden tener documentación parcial
- Los proyectos académicos pueden no tener métricas de producción
- Algunos proyectos pueden no tener demo desplegada
