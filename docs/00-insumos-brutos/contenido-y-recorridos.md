## 2. Recorridos por Tipo de Visitante

### 2.1 Reclutador Técnico

**Objetivo:** Evaluar rápidamente si el candidato es viable para una posición técnica.

**Recorrido Esperado:**
```
1. Hero Section (5 seg)
   → Entiende: Rol, especialidad, nivel
   → Decisión: ¿Seguir explorando?

2. Proyectos Destacados (1-2 min)
   → Entiende: Qué ha construido, con qué tecnologías
   → Decisión: ¿Tiene experiencia relevante?

3. GitHub (1-2 min)
   → Entiende: Calidad de código, actividad
   → Decisión: ¿Es apto para entrevista técnica?

4. CV (30 seg)
   → Entiende: Formación, experiencia formal
   → Decisión: ¿Cumple requisitos mínimos?
```

**Tiempo Total Estimado:** 2-3 minutos
**Contenido Crítico:** Hero claro, proyectos visibles, GitHub link

---

### 2.2 Director de Ingeniería / Tech Lead

**Objetivo:** Evaluar la profundidad técnica y el criterio de arquitectura.

**Recorrido Esperado:**
```
1. Hero Section (5 seg)
   → Entiende: Stack tecnológico principal

2. Caso de Estudio Detallado (5-10 min)
   → Entiende: Problema → Solución → Decisions → Resultado
   → Evalúa: Criterio técnico, trade-offs, métricas

3. Arquitectura y Código (3-5 min)
   → Entiende: Estructura del código, patrones usados
   → Evalúa: Calidad, mantenibilidad, testing

4. Otros Proyectos (2-3 min)
   → Entiende: Versatilidad, diversidad tecnológica
   → Evalúa: Capacidad de aprendizaje
```

**Tiempo Total Estimado:** 5-10 minutos
**Contenido Crítico:** Casos de estudio con narrativa técnica, GitHub con código limpio

---

### 2.3 Reclutador de RRHH / Non-Technical

**Objetivo:** Verificar que el candidato cumple requisitos básicos y es profesional.

**Recorrido Esperado:**
```
1. Hero Section (5 seg)
   → Entiende: Nombre, rol, profesionalismo

2. Sobre Mí (30 seg)
   → Entiende: Background, objetivos, disponibilidad

3. Habilidades (30 seg)
   → Entiende: Tecnologías que maneja

4. Contacto (30 seg)
   → Entiende: Cómo comunicarse
```

**Tiempo Total Estimado:** 1-2 minutos
**Contenido Crítico:** Hero profesional, biografía clara, contacto fácil

---

### 2.4 Posible Cliente (Freelance)

**Objetivo:** Evaluar si el desarrollador puede resolver su problema específico.

**Recorrido Esperado:**
```
1. Hero Section (5 seg)
   → Entiende: Qué tipo de desarrollo hace

2. Proyectos Relacionados (2-3 min)
   → Entiende: Si ha resuelto problemas similares
   → Evalúa: Calidad del trabajo, relevancia

3. Testimonios/Referencias (1 min)
   → Entiende: Experiencia de otros clientes
   → Evalúa: Confiabilidad

4. Contacto (1 min)
   → Entiende: Cómo iniciar una conversación
```

**Tiempo Total Estimado:** 3-5 minutos
**Contenido Crítico:** Proyectos relevantes, testimonios, contacto accesible

---

### 2.5 Desarrollador / Par

**Objetivo:** Evaluar la calidad técnica y aprender del trabajo de otro.

**Recorrido Esperado:**
```
1. Hero Section (5 seg)
   → Entiende: Stack tecnológico

2. Proyectos (3-5 min)
   → Entiende: Qué ha construido, cómo lo ha resuelto
   → Evalúa: Creatividad, eficiencia

3. GitHub (5-10 min)
   → Entiende: Código fuente, documentación
   → Evalúa: Calidad de código, buenas prácticas

4. Blog/Artículos (si existen) (5 min)
   → Entiende: Conocimiento profundo
   → Evalúa: Capacidad de comunicación
```

**Tiempo Total Estimado:** 5-10 minutos
**Contenido Crítico:** GitHub rico, documentación técnica, casos de estudio detallados

## 5. Copywriting Guidelines

### Tono de Voz
- **Profesional** pero no rígido
- **Directo** sin ser seco
- **Técnico** sin ser incomprensible
- **Confiente** sin ser arrogante

### Palabras Clave Incluir
- Desarrollador Full Stack
- Java / Spring Boot
- C# / ASP.NET
- React / Angular / Vue.js
- Arquitectura de software
- APIs REST
- Bases de datos
- Accesibilidad
- Rendimiento

### Palabras Clave Evitar
- "Experto" (usar "experiencia en")
- "100%" (ser realista)
- "Fácil" (respetar la complejidad)
- Jerga innecesaria
