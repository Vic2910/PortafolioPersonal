# AG-01: Reclutador Técnico / Director de Ingeniería

## Datos del Agente

| Campo | Valor |
|:------|:------|
| **ID** | AG-01 |
| **Nombre** | Reclutador Técnico / Director de Ingeniería / Tech Lead |
| **Objetivo** | Evaluar la idoneidad técnica del candidato para una posición de desarrollo |
| **Tiempo Promedio** | 2-5 minutos |
| **Prioridad** | Alta |

---

## Perfil

### ¿Quién es?
- Director de ingeniería o Tech Lead que busca incorporar talento al equipo
- Reclutador técnico con conocimientos en desarrollo de software
- Lead developer que evalúa candidatos para su equipo

### ¿Qué busca?
- Dominio技术和_stack tecnológico relevante
- Calidad de código y buenas prácticas
- Capacidad de resolución de problemas
- Experiencia en proyectos similares a los que maneja su equipo

### ¿Cómo evalúa?
- Revisión rápida del Hero Section (5 segundos)
- Exploración de proyectos destacados (1-2 minutos)
- Revisión de GitHub y código fuente (1-2 minutos)
- Análisis de casos de estudio si existen (3-5 minutos)

---

## Recorrido Esperado

```
1. Hero Section (5 seg)
   → Entiende: Rol, especialidad, stack principal
   → Pregunta: ¿Tiene experiencia relevante?
   → Decisión: ¿Seguir explorando?

2. Proyectos Destacados (1-2 min)
   → Entiende: Qué ha construido, con qué tecnologías
   → Evalúa: Complejidad, relevancia para su equipo
   → Pregunta: ¿Ha resuelto problemas similares?

3. GitHub (1-2 min)
   → Entiende: Calidad de código, actividad
   → Evalúa: Estructura, documentación, tests
   → Pregunta: ¿Es mantenible el código?

4. Caso de Estudio (3-5 min) - Si existe
   → Entiende: Proceso de toma de decisiones
   → Evalúa: Profundidad técnica, trade-offs
   → Pregunta: ¿Puede articular decisiones técnicas?

5. Contacto (30 seg)
   → Decide: Programar entrevista técnica
   → Acción: Enviar mensaje o email
```

---

## Criterios de Evaluación

### Must Have (Eliminación)
| Criterio | Descripción | Requisito |
|:---------|:------------|:----------|
| Stack relevante | Tecnologías que el equipo usa | Al menos 2 tecnologías coincidentes |
| Código visible | Repositorios en GitHub | Al menos 2 proyectos públicos |
| Proyectos completos | Trabajos terminados | Al menos 3 proyectos documentados |

### Should Have (Fortalezas)
| Criterio | Descripción | Ideal |
|:---------|:------------|:------|
| Arquitectura limpia | Separación de capas | Patrón MVC o similar |
| Tests | Pruebas automatizadas | Cobertura > 50% |
| Documentación | README detallado | Casos de estudio |
| CI/CD | Pipelines configurados | Deploy automático |

### Nice to Have (Diferenciadores)
| Criterio | Descripción | Valor Agregado |
|:---------|:------------|:---------------|
| Contribuciones OSS | Open source | Muestra comunidad |
| Blog técnico | Artículos publicados | Comunicación técnica |
| Certificaciones | Certificaciones técnicas | Formación formal |

---

## Contenido Crítico para Este Agente

### Hero Section
- Nombre y rol claramente visibles
- Stack tecnológico principal listado
- Enlace a GitHub prominente

### Proyectos
- Tecnologías usadas por proyecto
- Arquitectura aplicada
- Resultados y métricas

### GitHub
- Código limpio y organizado
- READMEs descriptivos
- Historial de commits reciente

---

## Preguntas que Este Agente se Hace

1. ¿Tiene experiencia con nuestro stack tecnológico?
2. ¿Su código es mantenible y limpio?
3. ¿Entiende arquitectura de software?
4. ¿Ha trabajado en proyectos de similar complejidad?
5. ¿Puede comunicar decisiones técnicas?
6. ¿Es autodidacta y aprende rápido?

---

## Errores que Provocan Rechazo

| Error | Impacto | Solución |
|:------|:--------|:---------|
| Sin GitHub visible | Alto | Mostrar repositorios |
| Código desordenado | Alto | Limpiar y documentar |
| Proyectos genéricos | Medio | Destacar complejidad real |
| Sin casos de estudio | Medio | Documentar proceso |
| Stack irrelevante | Bajo | Enfatizar transferibilidad |
